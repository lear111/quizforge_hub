# 登录与注册管理

入口：管理后台 → 登录与注册（`/admin/#authentication`）。登录固定需要账号和密码；注册固定需要用户名、账号和密码。用户名是显示昵称，账号是邮箱或中国大陆手机号。

| 独立开关 | 首次升级默认值 |
| --- | --- |
| 登录需要邮箱／短信验证码 | 关闭 |
| 登录需要人机验证 | 关闭 |
| 注册需要邮箱／短信验证码 | 开启 |
| 注册需要人机验证 | 开启 |
| 注册需要邀请码 | 保留原邀请码管理的选择 |

邮箱／短信验证码根据用户填写的账号选择一种发送，不要求两者都验证。所有组合都保留账号、密码校验；没有免密码登录。联系方式绑定仍固定要求当前密码、目标联系方式验证码和人机验证，不受这些登录、注册开关影响。

## 保存与生效

勾选后点击“保存并生效”；出现“已保存并立即生效。”才表示保存成功。未保存时页面明确提示。配置与操作日志在同一事务提交，日志失败则设置回滚。保存携带配置版本，另一个管理员已修改时拒绝覆盖，需重新读取。

邀请码管理保留生成、导出、兑换记录与停用，统一开关移至本页。旧邀请码设置接口仍兼容，操作会更新同一配置版本。关闭邀请码验证不会删除或消费已生成的邀请码。

用户登录、注册窗口打开、恢复前台、获取验证码和最终提交前都会刷新配置；窗口可见时每十秒检查一次。刷新保留已填的用户名、账号和密码，只调整验证字段。服务端在最终事务重新核对要求，不能凭尚未刷新的窗口绕过验证。

## 服务可用性

页面显示邮件、短信与人机验证配置是否可用，不显示密钥。发送服务与 Turnstile 分别配置，关闭注册人机验证后，可以单独使用已配置的邮箱／短信验证码。启用尚未配置的验证服务会被拒绝；启用登录验证码还要保证已有邮箱和手机号账号对应的发送通道可用，避免锁住已有用户。

如果关闭注册验证码，新账号的联系方式明确标为“未验证”；不伪造验证时间。之后通过登录验证码验证该联系方式时才更新状态。该标记随私有云端身份桥同步，不进入公开页面或设备授权令牌。

## 接口与持久化

- `GET /api/config`：公开要求 `authPolicy`、验证码通道 `verificationMethods` 和 `captchaReady`，兼容原 `invitationRequired` 字段。
- `GET /api/admin/authentication`：管理员读取开关、版本和服务可用性。
- `PUT /api/admin/authentication`：管理员提交布尔开关及 `revision`，沿用同源、管理员和 CSRF 检查。
- `POST /api/auth/login-code`：必须先核对账号、密码，再向该账号发送验证码；此请求不创建登录会话。

验证码保留六位、十分钟有效、最多五次错误尝试、重发替换旧码及持久化发送限制。注册、登录和绑定用途隔离；登录验证码同时绑定用户及当前密码版本。验证码只消费一次，全部验证成功后才创建会话。人机验证要求在发码后加强时，先前未通过人机验证的验证码不能满足新要求。

新增 `authentication_policy` 和 `unverified_contacts` 表；邮箱／联系方式验证码表新增 `captcha_verified` 列。旧验证码来自必选人机验证流程，因此迁移默认值为 `1`。升级不修改已有用户 ID、密码、余额、设备、题库或作答；原 `registration_policy` 继续存储邀请码选择。

## 登录故障恢复

若额外登录验证启用后外部服务故障，服务器运营者可为**已有管理员**执行：

```sh
sudo -u quizforge env DATA_DIR=/var/lib/quizforge-hub /opt/quizforge-node/bin/node /opt/quizforge-hub/current/scripts/admin.mjs auth-login-recovery admin@example.com
```

将示例账号替换为已有管理员邮箱或手机号。命令仅关闭两项额外登录验证，保留账号密码、所有注册设置和数据，并记录恢复审计；不会创建管理员或重置密码。无需通过恢复旧数据库来关闭验证。

## 验证范围

`test/auth-policy.test.mjs` 覆盖邮箱／手机的登录、注册验证组合，设置保存及重启、管理员权限和审计回滚、验证码用途与密码版本隔离、并发切换要求、未验证联系方式同步、服务缺失以及运营者恢复命令。浏览器验收使用临时合成账号、模拟验证码和模拟人机验证，不代表真实短信投递或真实 Turnstile 验收。
