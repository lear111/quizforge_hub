# 邮箱或手机号登录

本次源码基于 Hub 主线 `8878fd3`。仅修改 Hub；不修改 Web 或 Android，不改变已接入的设备授权协议 v1、回调地址、设备令牌格式和免费 AI 余额接口。手机号版本已部署至现有首尔测试服务器，私有配置由运营者填写；真实短信收码尚待运营者在页面完成。部署、备份和启停方式见 [测试服务器部署记录](../deploy/phone-auth-2026-10-23.md)。

## 用户行为

- 注册固定输入用户名、邮箱或中国大陆手机号和密码；默认还需要对应的六位验证码与人机验证，管理员可分别调整。验证一种联系方式即可，不要求同时提供邮箱和手机号。已有邮箱注册接口继续兼容。
- 日常登录输入邮箱或手机号和原密码；管理员可选配验证码和人机验证，首次升级默认关闭这两项额外登录要求，见 [登录注册管理说明](AUTH_POLICY.md)。没有免密码登录或自助密码找回。
- 手机号统一保存为 `+86` 格式。接入的 PNVS 产品当前仅支持中国大陆号码，不把海外号码静默改成国内号。
- 邀请码开关对两种注册方式一致生效：发码前校验，最终账号事务中再次校验并消费。验证码错误、联系方式冲突和邀请码已消费均不留下半个账号。
- 在 Hub“我的分享 → 账号联系方式”可以补绑原账号缺少的另一种联系方式，需输入当前密码、通过人机验证并填写目标联系方式收到的验证码。绑定仍使用原 `users.id`；不生成第二个账号，不重置余额、空间、题库、设备或兑换记录。
- 一个邮箱或手机号最多属于一个账号。此入口不支持覆盖已有联系方式、解绑或合并两个已有账号；不能凭新号码验证码取代原账号的密码验证。
- 联系方式仅返回给本人和原有授权管理接口，不进入公开题库、评论、设备令牌响应或模型提示词。云端用户中心和管理列表支持显示手机号账号。

## 服务器配置

使用阿里云中国站“号码认证 → 短信认证”，不是普通短信服务。个人实名认证账号可使用平台提供的配套签名、模板。选择包含 `code` 和 `min` 两个变量的登录/注册模板。

配置示例见 `deploy/sms.env.example`。在服务器上由运营者填写 `/etc/quizforge-hub/sms.env`，权限 `0600`；主 Hub 的 systemd 示例按可选环境文件加载它，练习服务不需要短信密钥。本机隔离调试可显式设置 `SMS_ENV_FILE` 指向仓库外文件；不会搜索或复制其他项目的凭据。

专用 RAM 身份只需发送验证码操作：

```json
{"Version":"1","Statement":[{"Effect":"Allow","Action":["dypns:SendSmsVerifyCode"],"Resource":"*"}]}
```

本实现由 Hub 使用密码学随机数生成验证码，以 HMAC 摘要保存并在 SQLite 中原子校验/消费；通过 `TemplateParam` 将该验证码交由阿里云发送。阿里云文档明确支持此模式，但自定义验证码不能交由 `CheckSmsVerifyCode` 校验，因此本实现不申请该接口权限。验证码不进入 API 响应、日志或公开配置。

`ALIYUN_SMS_ENABLED=0` 为默认值。短信发送需要密钥、签名、模板和随机摘要密钥。默认注册还需要正式 Turnstile 配置；管理员明确关闭注册人机验证后，发送服务可独立使用。绑定联系方式始终需要人机验证。已有设备令牌继续按原规则工作，邮箱发送通道独立配置。

付费发送使用固定的 `https://dypnsapi.aliyuncs.com/`，ACS3-HMAC-SHA256 签名，无 Cookie，不跟随重定向，不自动重试，并禁用接口的自动补发。发送请求最长十秒。号码一分钟一次、滚动一天五次；IP 十分钟五次、一天二十次；全站滚动一天默认最多预留一百次，可用 `SMS_DAILY_LIMIT` 调整。发送失败和超时仍保留预留，避免不确定投递结果造成重复收费。这是应用发送次数上限，不替代云账号账单管理。

验证码六位、十分钟有效、最多五次错误尝试，重发替换旧码。发送量和错误次数持久化，绑定验证码同时绑定目标账号和用途，不能用于注册、另一用户或另一联系方式。

## 数据与兼容性

旧 `users.email NOT NULL` 在启动时以事务改为可空；保留六列及现有 ID、密码、管理员状态和创建时间。电话号码单独保存于 `user_phones`，绑定唯一用户，记录验证时间。迁移保留原用户表的自建索引和触发器，并在提交前检查外键完整性；未知用户表结构会拒绝迁移，避免丢列。

AI 余额、兑换流水、已连接设备、会话和题库继续以用户 ID 关联。`/api/connect/token` 与 `/api/connect/me` 的客户端用户信息仍为昵称，手机号和邮箱不进入设备令牌接口。Hub→云端练习的私有身份桥兼容邮箱为空及已验证手机号，保持原来的 origin 和权限校验。

私人交付及额度调整读取的接收人资料与登录共用 `accountProfile`，包含手机号和未验证联系方式标记，保留原创建时间且不返回密码。手机号账号无需先绑定邮箱或访问练习空间即可接收交付。普通登录桥同样保留验证标记；后续完成手机号验证再同步时补记验证时间，已验证的同一号码保留原时间。缺失或封禁用户、非管理员和不受信任来源仍会拒绝，校验不会因兼容手机号而放宽。

该私人交付兼容修复已更新首尔测试服务器，复现、回归与备份见 [部署记录](../deploy/private-delivery-2026-10-23.md)。

部署前需停止写入并完整备份 Hub、练习服务的数据目录。两服务应同时更新身份适配，确认旧账号登录与额度，再开放手机注册。创建手机号账号后，不能直接切回假设邮箱必填的旧版代码；优先关闭新短信发送但保留已接入的账号兼容层。恢复备份前需核对备份之后的题库、作答及余额变更，不能盲目覆盖。

## 验证范围

`node --test test/phone-auth.test.mjs` 使用临时数据库、合成账号、模拟短信/邮件及人机验证，覆盖手机号归一化、官方签名参考向量、验证码用途/账号隔离、错误次数、超时并发预留、邀请码、邮箱补绑、两类客户端的真实 HTTP 授权协议、余额/设备/流水保留、旧表迁移和手机号身份适配。协议测试不是实际 Android 系统唤起或真机验收，也没有调用付费模型或真实短信。

正式开通后还需验证国内服务器发码、手机实际收码、失败提示和供应商账单。不得以模拟供应商测试代替收码验收。

2026-10-22 本地验收结果：

- 手机验证专项 **13/13** 通过；包含补绑后两类设备令牌继续评分、同一余额扣费、手机号身份经过实际 Hub 会话桥，以及两次注册争用同一邀请码的原子回滚。
- 最终登录/邮箱/邀请/云端 AI 组合 **26/26** 通过。金额均来自合成账本，上游为模拟响应。
- Web 测试运行时从 Git 提交 `2ad03a1b842f3b74180c6a6f7b45f3a3cc35a43c` 的归档构建，不读取正在改动的 Web 工作区；与 Hub 锁定清单 **239 个输入文件逐一匹配**。运行快照和依赖保持在忽略目录中。
- 完整套件一次运行 **99 项：96 通过、1 失败、2 跳过**。失败为既有 `/api/cloud/ai/credential` 在免费 AI 未配置时错误返回 503；现已在服务可用性判断前明确拒绝未知路由，保持 404，不开放任何凭据读取。修复后手机/云端资源/AI 相关 **19/19** 通过；未将两次运行的用例数相加。完整运行中的手机用例尚为 11 项，随后新增的 2 项已纳入上述最终专项及组合复测。
- 两项跳过分别为 Windows 无符号链接权限的 CLI 启动检查，以及本隔离工作区没有旧运行时的多题库合并用例；后者不等于旧账号表迁移，本次的旧账号 ID/会话/令牌/余额/外键迁移用例已实际通过。
- 实际内置浏览器完成手机号注册、短信通道切换、发送反馈及倒计时、补绑邮箱、邮箱密码登录和手机号密码登录。全部使用 loopback 临时服务、合成联系方式和模拟人机验证/投递；没有触发真实 CAPTCHA、真实短信或生产账户。界面截图保存在本地忽略目录 `.runtime/phone-account-browser.png`。
- Git 差异及全部改动 JavaScript 语法检查通过；未修改 Web、Android、当前主工作区或线上服务。
