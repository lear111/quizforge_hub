# Hub → 本地 QuizForge 导入协议 v1

日期：2026-10-20。状态：Hub 已于 2026-10-20 部署到正式题库广场并启用本地导入；接口与网页、Web 启动器协议均已实现并完成隔离联调。公网检查发现的客户端 .NET 4.8 目标框架遗漏已在独立 Web 修复分支提交并生成修正版安装包，用户尚需覆盖升级；真实浏览器到 Windows 的唤醒仍待验收。详见同目录验收记录与部署记录。

## 1. 目标与分工

用户在 Hub 题库详情点击“下载到本地”，浏览器请求打开 Windows QuizForge。启动器启动或唤醒已有进程，从官方 Hub 下载确定版本的题库，调用已有导入流程，成功后打开本地刷题页并选中新题库。

- Hub 会话负责：网页入口、公共下载协议、版本与审核状态校验、流量计数、Hub 测试及本地端对接说明。
- 本地 Web 会话负责：Windows 安装器协议注册、启动参数、进程唤醒、下载与校验、导入队列、客户端测试及安装包。
- 当前会话不修改本地启动器，不向其他会话自动发消息。用户可将本文末尾的对接任务复制过去。
- 首版限 Windows 10/11 x64 安装版与已审核公开的 `.qbank`。ZIP、RAR、7Z 保留普通文件下载；不改名冒充 `.qbank`。解压版保留已有文件导入能力，不自动注册协议。
- `.qbank` 只是文件后缀。导入只支持包内 `formatVersion: 3` 的单题库包和分组包，明确拒绝格式 1、2，并提示需要制作者升级题库包。打包格式版本与题目内容年份、题库自身版本号及 Hub 发布修订号 `revision` 无关；历史题目按格式 3 打包即可导入。
- 首版不做私人题库跨端传输、客户端登录 Hub、网站查询本机任务、安装检测或已导入题库的在线覆盖更新。

成功标准：未启动和已启动两种情况均能导入；错误文件不进入现有题库；原题库、答案、设置、历史保持原有语义；网站不会把“请求唤醒”显示成“导入成功”。

## 3. 唤醒链接与 Windows 接入

规范链接：

```text
quizforge://hub/import?v=1&pack=123e4567-e89b-42d3-a456-426614174000&revision=3
```

- scheme 为 `quizforge`，host 为 `hub`，path 为 `/import`；不带用户名、密码、端口、fragment 或结尾斜杠。
- query 恰好包含 `v`、`pack`、`revision` 各一次，顺序不限。未知字段、重复字段、编码后的字段名和值均拒绝；v1 值均为 ASCII，不需要百分号编码。
- `v` 必须是字面量 `1`；`pack` 为小写十六进制的标准 8-4-4-4-12 UUID；`revision` 为不带前导零的十进制正整数，最大 `9007199254740991`。
- URI 全长最多 1024 个字符。不接受空白、控制字符、反斜杠、引号或通过 URI 指定任意下载地址、本机路径、启动参数。
- 本地客户端固定官方 origin 为 `https://quizforge.treenewbee.cloud`，不从 URI、清单、网页标题或错误信息读取服务器地址。

安装器注册当前用户的 `Software\Classes\quizforge`，设置空字符串 `URL Protocol`，打开命令使用双引号包裹的安装路径和完整参数：

```text
"<安装目录>\QuizForge.exe" --open-url "%1"
```

`--open-url` 模式只接受这两个参数，与 `--import`、`--root`、`--data-root`、`--quit` 等其他模式互斥。直接解析 URI，不经 shell 或拼接命令执行。URI 注册指向受控安装目录；卸载只清理仍指向本安装位置的注册项，不删除其他程序或其他安装位置接管的项。遇到其他程序占用协议时保留原注册并提示冲突，不静默覆盖。

已有实例接收恰好两个字段的管道消息：`{"command":"hub-import","uri":"<完整 URI>"}`。发送方和接收方都验证 URI；管道继续限制为当前 Windows 用户。未启动时复用现有后端启动与就绪等待。由导入任务冷启动时，成功后才打开题库页面，不先打开一个空白练习页。

## 4. Hub HTTP 契约

### 4.1 能力开关

增加 `LOCAL_IMPORT_ENABLED=1` 和等价测试选项 `localImportEnabled`，默认关闭，独立于 `CLOUD_ENABLED`。`GET /api/config` 增加：

```json
{"localImport":{"enabled":true,"protocolVersion":1,"scheme":"quizforge"}}
```

上例只是新增字段，原有配置字段保留。关闭时 `enabled:false`，网页使用原有文件下载；新增清单和固定版本下载模式返回 404 / `LOCAL_IMPORT_DISABLED`。后端可先发布，待兼容客户端可供安装后再启用入口。

### 4.2 获取固定版本清单

```text
GET /api/packs/<packId>/local-import?revision=<revision>
```

只接受一个合法 revision 参数；不需要登录，且即使请求有作者或管理员 cookie，也只允许读取当前 `approved` 的公开题库。待审、驳回、删除题库统一返回 404，不复用作者可读取未公开附件的例外。

200 响应示例（字段类型和命名为正式约定）：

```json
{
  "schemaVersion": 1,
  "pack": {
    "id": "123e4567-e89b-42d3-a456-426614174000",
    "revision": 3,
    "title": "基础题型展示"
  },
  "archive": {
    "name": "基础题型.qbank",
    "size": 123456,
    "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
  }
}
```

示例不是可下载的真实文件。`size` 为整数原始文件字节数，范围 1–67108864；SHA-256 为 64 位小写十六进制；name 仅作为展示名，扩展名必须为 `.qbank`（大小写不敏感）。服务器同时受现有更小的上传上限约束。

清单不返回任意 URL 或服务器文件路径。读取和检查附件后、发送清单前，服务器重新核对公开状态、revision 与同一文件记录；不能在异步读取期间更新后返回混合版本信息。客户端检查 schemaVersion、pack ID、revision、必需字段和边界，允许忽略新增 JSON 字段。响应使用 JSON 和 `Cache-Control: no-store`，客户端最多读取 32 KiB；错误响应也使用同一读取上限。清单请求受每 IP 每分钟 60 次限流，不增加下载次数或下载流量，不建立登录会话。

### 4.3 下载确定的字节

客户端根据自身验证过的字段构造以下固定路径，SHA-256 来自清单：

```text
GET /api/packs/<packId>/download?revision=<revision>&sha256=<sha256>
```

- 同时带 revision 和 sha256 时进入固定版本模式。任一出现但另一项缺失、重复、格式错误，必须返回 400，不能退回普通下载。固定版本模式不接受额外 query 参数。
- 重新验证公开审核状态、revision、归档类型、大小和 SHA-256。清单已成功不代表后续下载获准；已更新、待复审或下架的旧链接不能下载新内容。
- 先打开对应不可变附件文件，再在流量预留前复核数据库里的公开状态、revision、文件 ID、大小和 SHA-256；复核到流量事务完成之间不插入异步等待。复核失败关闭文件句柄，不计数。响应从同一个文件句柄发送，避免在校验后按路径读到替换文件。
- 成功为 200，沿用现有 `application/octet-stream`、准确 Content-Length、附件文件名及 `Cache-Control: private, no-store`。不重定向，不用 Range 或断点续传。已开始的下载不承诺在随后下架时即时中止；新请求必须重新准入。
- 每次成功准入下载预留一次文件完整大小，并增加一次下载次数。沿用现有保守预留方式，中途断网不退还本次预留；不宣称计数等于实际发出的字节。拒绝请求与清单请求不扣额度。
- 原有不带 revision/sha256 的 `/download` 保持权限、计数及普通文件下载行为，不要求旧网页、作者预览和第三方下载工具升级。

原生客户端请求不带 Hub cookie、HTTP 认证或浏览器登录令牌，使用既有匿名公共下载语义：计入站点和下载请求 IP 的额度，不归入某个云端账户，也不占云端用户存储。不得相信客户端自报 userId 将流量计到他人名下。私人/按账户授权的跨端下载另立后续协议，不在 v1 中夹带登录凭据。

### 4.4 错误

新清单和固定版本下载在既有 `error` 字段之外返回稳定的 `code`，不改变旧接口错误结构。以下是 v1 必需代码；客户端对未知代码或旧服务器无 code 的响应仍能安全失败。

| HTTP | code | 触发与客户端提示 |
| --- | --- | --- |
| 400 | `LOCAL_IMPORT_REQUEST_INVALID` | 参数不合法；提示链接无效 |
| 404 | `LOCAL_IMPORT_DISABLED` | 能力关闭；提示回 Hub 下载文件或稍后重试 |
| 404 | `LOCAL_IMPORT_UNAVAILABLE` | 不存在、非公开、缺失附件；提示题库暂不可用 |
| 409 | `LOCAL_IMPORT_REVISION_CHANGED` | 当前 revision 或文件摘要与请求不同；提示刷新 Hub 后重新点击，不自动换版 |
| 413 | `LOCAL_IMPORT_TOO_LARGE` | 超过客户端共同上限；提示文件过大 |
| 422 | `LOCAL_IMPORT_FORMAT_UNSUPPORTED` | 公开附件不是 `.qbank`；提示使用文件下载 |
| 429 | `LOCAL_IMPORT_RATE_LIMITED` | 清单或下载频率过高；提示稍后重试 |
| 429 | `LOCAL_IMPORT_TRAFFIC_LIMIT` | 站点/IP 下载预算不足；显示可读提示，不自动重试 |
| 500 | `LOCAL_IMPORT_SERVER_ERROR` | 内部故障；返回通用提示，不泄露服务器路径或堆栈 |

旧 Hub 返回的不带 code 的错误，或代理返回的 HTML、超大响应、非预期 Content-Type 均按下载失败处理，不交给题库导入器。请求既不可用又版本过期时优先返回不可用，避免暴露非公开版本信息。

## 5. 本地下载与导入

1. 验证 URI，通过现有当前用户单实例渠道建立任务。待处理键为 `hub:<packId>:<revision>`；相同键尚未完成时合并为同一任务，不能重复下载或导入。
2. Hub 任务和本机文件任务共用串行队列与最多 20 个待处理任务的容量。等待现有后端 ready 成功后，依次获取清单、下载、校验、调用 `LocalPackageImport.Upload`；退出等待已接受任务的行为与现有文件导入一致。
3. HTTPS 请求使用系统证书验证，不跟随重定向，不携带 cookie、默认身份凭据或 Hub 登录信息。总网络阶段限时 180 秒（包含清单和下载）；不自动网络重试，不信任服务器要求改到其他 origin 的响应。只请求固定两种 API 路径。
4. 仅在当前数据目录下自行创建随机任务暂存目录，固定暂存名 `package.qbank`；不把远端文件名用于路径。流式写入并计算 SHA-256，Content-Length 必须与清单 size 相同，实际字节数必须完全相同且不超过 64 MiB。超限、截断、附加内容、摘要不符均在导入前拒绝。
5. 通过后调用原有本机二进制导入接口，由现有包校验器读取包内 `formatVersion`，只接受格式 3 的单题库包和分组包；格式 1、2 返回现有 `422 UNSUPPORTED_LIBRARY_ARCHIVE`，提示需要制作者升级题库包，不尝试旧格式导入或自动迁移。继续执行资源、路径、拓展兼容与规则隔离校验。后缀、公开审核或 SHA-256 校验通过都不能替代包格式验证；不新增 HTTP 任意路径读取或公共远程控制接口。
6. 导入成功复用已有 `imported-bank` 路由提示、新页面打开、分组包首个题库选择、题库和拓展统计。已有答题页面不被刷新。未知或损坏包按现有导入事务失败，不覆盖现有内容。
7. 成功或失败均关闭文件句柄、删除本任务暂存并释放待处理键。若文件被占用暂时不能删除，只保留在专用暂存目录并记清理失败；下次启动只清理该目录内超过 24 小时且非活动任务的残留，不触及用户题库或普通上传文件。

已有语义保持：任务完成后再次明确点击同一链接，仍导入一个独立副本；首版不因相同 pack/revision 合并或更新已有题库，不改变本地稳定 ID、拓展绑定和历史记录的兼容规则。失败不会自动再导入；用户可以重新点击重试。

任务状态沿用 `pendingImports` / `lastImport`；Hub 任务补充来源 packId、revision，state 使用 `queued`、`downloading`、`importing`、`completed`、`failed`。进度与可读失败原因在托盘和运行情况显示。来源记录限任务状态，不为持久化来源另行修改题库导入接口。

## 6. Hub 页面行为

- 能力开启、题库已审核且附件名为 `.qbank` 时，显示“下载并导入到本地”，使用由详情 DTO 的 pack ID/revision 同步构造的 `quizforge://` 链接。Windows 与 Android 共用该链接，由当前设备系统唤起，无需选择平台。本地说明为“导入当前设备上的 QuizForge，支持电脑和安卓手机、平板。”链接通过真实用户点击激活，不在点击后等待网络请求再尝试唤醒，也不在页面加载时自动唤醒。
- 点击后仅显示“已请求打开 QuizForge，请在系统提示中允许打开”。网页不靠失焦、计时器、隐藏 iframe、localhost 探测或跨站回调判断是否安装或成功，不循环唤起。
- 同处始终提供“下载题库文件”和“安装／升级 Windows 版”。普通下载继续使用现有下载检查与下载路由，公开下载无需登录；Windows 安装链接使用 Hub 已有安装指引入口 `/`，不指向开发测试文件。Android 显示“安装包待发布”，正式发布地址与签名确定后再配置。
- 用户取消浏览器提示、没有安装协议处理程序或使用旧客户端时，自行选择上述备用入口；不自动反复弹出外部应用，不自动同时开始文件下载。
- 对公开 ZIP、RAR、7Z 显示“下载题库文件”，不提供直接导入链接；作者和管理员查看未公开题库时也只保留原有授权文件下载。
- 获取新详情或版本变化时重新构造链接；旧页面已显示的旧 revision 由客户端和服务端拒绝，提示回到 Hub 刷新。
- “下载并导入到云端”保留为另一条现有流程，说明为“导入账号的云端题库，需登录。”本功能不修改云端登录要求、题库广场入口、云端练习或管理员页面。

以上网页文案于 2026-10-21 按 Android 交接更新，未修改 v1 清单或下载协议。本文第 5 节描述原有 Windows 客户端；Android 交接报告的队列去重、代理和兼容范围以各自客户端实现为准，Hub 不推断客户端导入结果。当前提交的验证范围与仍待联合验收项见 [Android 一键导入交接](../../HUB_ANDROID_IMPORT.md)。

## 7. 修改边界与发布协作

Hub 修改集中在 `server.mjs` 的能力配置、清单/下载路由与流量准入，`public/app.js` 的详情入口和提示，以及对应 Hub 测试。可以提取专用本地导入模块以保持路由清楚，不同时重构账户、云端运行快照或其他下载流程。

本地修改集中在 `Program.cs`、`TrayContext.cs`、导入队列、一个专门的 Hub 下载/URI 解析模块、安装器注册及桌面测试；复用现有上传与本地网页选库，不复制 Hub 或整套 Web 核心。

流程为关联的 Web PR 和 Hub PR：共享 v1 文档 → 两侧实现与各自检查 → 合并并提供兼容本地安装包 → Hub 服务部署但能力开关保持关闭 → 真实浏览器与安装包验收 → 开启入口。旧 Web 仍可用文件下载；旧 Hub 不支持清单时，新客户端明确失败并提示回站下载文件。

本地安装包和 Hub 仍独立发版，不要求相同版本号；协议能力以 v1 标识，不编造尚未发布的最低客户端版本。Hub 该 PR 本身不要求升级刷题核心快照；若因实际依赖新增共享核心变更，按 Web 合并后 Hub 锁定提交的既有流程处理。

Hub 线上入口属于原公共 Hub 服务 `quizforge-hub`，不是练习站。部署前应把现有未提交云端改动和本功能变更整理为可审查提交，保留原站数据、审核状态和配置备份；不能为发布此按钮把整个混合工作区直接覆盖到线上。回退时先关闭能力，普通文件下载继续工作；客户端数据与题库格式无需迁移。

## 8. 验收清单

所有测试使用隔离的示例题库、测试数据目录和注册项；不上传商业资料，不修改用户正在使用的题库、答案或真实协议关联。HTTP 自动测试与实际 Windows 浏览器验收分别记录。

| 范围 | 必须覆盖 | 通过条件 |
| --- | --- | --- |
| URI/参数 | 标准链接、错误版本、重复/未知字段、编码、引号、控制字符、超长、混用启动参数 | 只接受规范 v1；非法输入不启动下载、不执行额外命令 |
| Hub 权限 | 公开、待审、驳回、删除；匿名、作者、管理员 | 新接口仅公开内容可用，不受作者/管理员例外绕过 |
| 固定版本 | 清单前更新；清单后更新/下架；附件替换及校验/打开竞态 | 不静默换版，准入前失效请求不扣流量、不发文件 |
| 格式与字节 | 非 `.qbank`、大小超限、长度缺失/不符、截断、额外字节、摘要不符、伪 JSON、重定向 | 下载/校验失败时现有导入器不被调用，暂存清理 |
| 流量与频率 | 清单重复、准入拒绝、正常下载、断流、预算不足、速率超限 | 仅每次已准入二进制下载预留一次完整文件大小，旧接口回归通过 |
| 队列与数据 | 冷启动、已有实例、同链接连点、Hub/文件混合队列、超 20 个任务、退出等待 | 单实例串行、待处理去重；完成再点生成独立副本；原数据不变 |
| 包格式 | `formatVersion: 3` 的单题库包和分组包（含历史年份题目）、格式 1/2 的旧格式包、损坏/不支持包 | 支持格式 3；明确拒绝旧格式包并提示制作者升级；失败保留现有内容，不按题目年份或题库自身版本号判定 |
| 网页与备用 | 开关关闭、旧/未安装客户端、取消提示、ZIP/RAR、文件下载、安装链接 | 无误报成功、不自动重复唤醒；备用下载可用 |
| 安装器 | 干净安装、升级、协议冲突、卸载、路径含空格/中文 | 真实 URI 命令引用正确，仅更新/清理本应用拥有的项 |
| 端到端 | Windows 上实际浏览器点击；客户端未运行和已运行各一次 | 浏览器外部程序提示正常；下载、导入、打开正确题库全链路通过 |

自动化测试可通过内部依赖注入使用本机测试 HTTP 服务，正式 URI/发行包不能通过参数或环境变量把官方服务器替换为任意地址。安装器测试继续使用独立 AppId、测试 scheme 和隔离目录，不占用正式 `quizforge` 注册项。端到端未完成前，只能报告接口或自动测试通过，不能报告完整唤醒导入已完成。

## 9. 可复制给本地 Web 会话的任务

> 请按本文件“Hub → 本地 QuizForge 导入协议 v1”对接 Windows 本地端：注册当前用户 quizforge URI，严格处理 `--open-url` 与 `hub-import` 管道命令，复用现有单实例/导入队列；只从固定官方 Hub 获取清单及固定 revision、SHA-256 的附件，限流式 64 MiB、180 秒网络阶段、拒绝重定向和凭据传递，校验后调用已有本机文件导入。包格式只支持 `formatVersion: 3` 的单题库包和分组包，明确拒绝格式 1、2 并提示制作者升级；不要与题目年份、题库自身版本号或 Hub revision 混淆。保持原题库、答案和历史，完成后打开选中新题库；补齐规范解析、下载失败、冷启动/热启动、队列去重及安装器隔离验证。Hub 会话负责服务器与网页，不在本地仓库复制 Hub 实现。先核对本地当前未提交工作和本文状态，文档获准且两端接口一致后再进入实现阶段。

参考：[Windows URI 启动机制](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-default-app)、[Inno Setup 注册表项](https://jrsoftware.org/ishelp/topic_registrysection.htm)。
