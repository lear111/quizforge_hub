# Hub 练习入口、三种下载与邀请注册

## 用户流程

- Hub 顶部“进入练习”前往 `https://practice.treenewbee.cloud/`，复用 Hub 登录。
- 已审核公共 `.qbank` 详情有“下载题库文件”“下载并导入到本地”“下载并导入到云端”。本地通过同一个 `quizforge://hub/import` 协议唤起当前设备的 Windows 或 Android 客户端，无需选择平台；云端仍需登录。文件下载保留原接口和匿名访问。ZIP、RAR、7Z 和未公开附件不显示直接导入按钮。
- 本地点击只显示已请求系统打开，不检测安装状态或判断导入结果。Windows 安装链接沿用现有入口；Android 发布地址和正式签名确定后再配置。实现与验收边界见 [Android 一键导入交接](./HUB_ANDROID_IMPORT.md)。
- 云端下载进入练习域的确认页；未登录则完成原有一次性授权码登录，并回到同一份题库。用户确认后，以同源 POST 导入并打开练习。已有同来源、同 revision 的副本直接提供打开链接，不重复占用空间。
- 云端从固定 Hub HTTPS 地址读取公开清单并下载固定 revision/SHA-256 的文件。不接收任意来源 URL、不转发 Cookie 或密钥、不跟随重定向；限制清单 32 KiB、文件 64 MiB、总网络时间 180 秒与一个在途下载。临时文件在成功或失败后清理。
- 云端继续使用格式 3 导入、拓展摘要审核、用户隔离和展开后空间记账。文件格式 1、2 不能导入。

## 邀请注册

`INVITATION_REQUIRED=1` 开启邀请制。默认关闭以兼容独立测试；线上 Hub 通过独立 systemd override 开启。原有账号无需邀请码即可登录。

发邮箱验证码与注册均须提供有效邀请码；人机验证、邮箱验证码及现有限频继续保留。邮箱验证失败、密码/昵称不合规或账号创建失败不会使用邀请码。账户创建、邀请码兑换及邮箱验证码消费处在同一个 SQLite 写事务中，并发注册只能成功一次。这里限制的是每码一个账号，不能识别一个自然人持有码的数量。

邀请码由密码学随机数生成，含 128 位随机值。数据库仅保存摘要与识别前缀，完整码只在创建时输出一次。保存创建者、兑换账号、有效期、停用时间及操作审计。已兑换的码不能通过停用撤销其账号。

## 临时管理员命令

管理员面板后续再做。当前命令须在服务器上通过有数据库访问权的维护者运行，并指定已有管理员邮箱。`DATA_DIR` 必须指向原 Hub 数据目录，不能指向练习域的镜像用户库。

```bash
cd /opt/quizforge-hub/current
export DATA_DIR=/var/lib/quizforge-hub
/opt/quizforge-node/bin/node scripts/admin.mjs invite-create 管理员邮箱 10 30
/opt/quizforge-node/bin/node scripts/admin.mjs invite-list 管理员邮箱
/opt/quizforge-node/bin/node scripts/admin.mjs invite-revoke 管理员邮箱 邀请码ID
```

创建示例为 10 个、有效期 30 天，每次最多 100 个，最长 365 天。建议用 `umask 077` 并将创建命令输出保存到仅维护者可读的文件，再逐个发放。列表只显示识别前缀、状态及已兑换账号，不再显示完整邀请码。生成邀请码不会向用户自动发消息。

## 部署边界

Hub 设置 `PRACTICE_ORIGIN=https://practice.treenewbee.cloud`，不需要启用原 Hub 的 `CLOUD_ENABLED`。练习服务增加固定 Hub 来源适配，沿用原 Web 运行快照。

发布前备份两个服务的数据目录；为两个服务建立独立发布目录后切换。重启练习服务会让内存中的登录授权失效，用户重新经过 Hub 登录即可恢复；已保存的题库和练习状态保存在原数据目录。回退时恢复旧发布软链接和本次 override，不能直接恢复旧数据库覆盖发布后的用户写入。
